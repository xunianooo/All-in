# 账号 JSON 文件导入与导出

适用：All In 1.2.40-test（46）及以后。账号文件含可用于登录的凭据，请只保存到自己可信的设备或存储位置，不要发布到群聊、工单或代码仓库。

## 手机使用

进入「供应商」并打开具体供应商，在账号卡片使用「导入账号」「导出账号」。已有按钮使用新的文件流程；支持的其他供应商补齐对应入口。此流程需在 Android 应用内使用，电脑浏览器管理页会明确提示返回手机，不会退回到复制或弹窗展示凭据。

### 导出

1. 勾选需要的账号或独立 API Key。默认勾选当前供应商，可以跨供应商多选。
2. 阅读凭据保存提示。
3. 在系统“另存为”中选择位置，建议设备本地「下载」目录。
4. 应用写入并重新读取校验文件后，才提示导出成功。

已被账号持有的镜像 Key 不重复导出；独立 Key 保留。账号的 `enabled` 和独立 Key 的 `off`/`enabled` 标记保留，不改变其他供应商设置。取消或文件写入失败不会改动账号；保存发生 I/O 故障时，目标文档可能不完整，请按应用失败提示检查，不把“打开了保存窗口”当成功。

### 导入

1. 从系统文件选择器选取 JSON。
2. 自动识别供应商并展示新增、待更新、重复或无效记录。一份混合文件会分别归入对应供应商，不会全部塞入打开入口的那一家。
3. 未识别记录可以逐条指定供应商，或者跳过。
4. 默认只勾选新增记录。相同身份而资料不同的条目，需要主动勾选并再次确认更新。
5. 保存后显示新增、更新及跳过数量，并刷新账号页。

完整重复记录不会再次入库；同名不等于同一账号，身份按供应商、账号标识、地区/域及团队等隔离。预览后本机配置发生变化，会要求重新预览，避免用旧文件快照覆盖刚刷新的凭据。所选批次在一次原子文件写入成功后才发布到内存，失败不会保留“仅在内存里”的新导入账号。

## 格式支持

- All In `all-in-accounts` v1：标准格式，包含一个或多个供应商。
- 旧版账号对象数组：没有供应商标识时，使用用户打开入口所明确选择的供应商。
- All In 配置 JSON：只提取供应商账号/Key 部分，不恢复网关口令、路由和其他整机配置。
- OpenCode / Magpie 按 `provider` 或 `provider#slot` 保存的 OAuth/API 认证字典，以及 Magpie `plugins` 字典。仅适配 All In 已实现的对应供应商；不是所有 Magpie 加密备份和宿主专有登录方式都可直接读取。
- Codex `auth.json` 的 `tokens` 与 `auth_mode` 结构；OpenCode 认证字典中的 OpenAI OAuth 对应 Codex 账号入口，不能把订阅会话当成普通 OpenAI API Key。
- ZCode 3.17.2 把会话保存在 OAuth `refresh` JSON 字符串的结构：分开保留会话/JWT/原设备资料与独立订阅 Key，不把付费 Key 当作赠送 JWT。
- Antigravity `refreshToken|project` 结构，拆分保存原刷新令牌及项目；Qoder 的 job/device 凭据分别保留，到期时间映射到本机字段。

UTF-8、UTF-8 BOM、带 BOM 的 UTF-16 LE/BE 均可解码。初始安全上限为 4 MiB、1024 条记录；畸形 JSON、重复字段、异常嵌套、脱敏密钥引用及矛盾字段拒绝导入。未知软件格式需通过脱敏样本确认，不按文件名或 Token 前缀猜测供应商。

标准文件结构示例（只有不可用占位值）：

```json
{
  "format": "all-in-accounts",
  "version": 1,
  "exportedAt": "2026-11-14T10:00:00.000Z",
  "providers": [
    {
      "id": "workbuddy",
      "accounts": [
        {
          "name": "示例账号",
          "type": "oauth",
          "token": "EXAMPLE_ONLY_NOT_A_TOKEN",
          "access": "EXAMPLE_ONLY_NOT_A_TOKEN",
          "refresh": "EXAMPLE_ONLY_NOT_A_REFRESH_TOKEN",
          "uid": "EXAMPLE_USER",
          "enabled": false
        }
      ],
      "keys": []
    }
  ]
}
```

## 安全及迁移边界

- 账号 JSON 是明文可迁移格式；原有加密整机备份仍独立保留，不用专有加密格式替代本功能。
- 真正凭据只在原生文件流程中处理，不放入 JavaScript、剪贴板、日志或 Activity 的保存状态 Bundle。界面回执只有数量和操作状态。
- 账号续期资料、可迁移设备认证信息及相关已消费/未知刷新保护按账号携带。不导出设备的整个刷新围栏文件或 MiniMax 的 HMAC 私钥。
- 导入不会发起推理、领取奖励或强制刷新；迁移当日建立保守签到保护，不把文件里的“成功”字段当作新的官方奖励证明。
- 导入成功仅代表资料保存成功，不代表平台仍认可凭据。过期、资料不完整、平台硬件绑定或桌面专属宿主依赖仍可能要求重新授权。
- 不支持的地区/协议或占位供应商不会伪装为可用。替换旧账号时，缺少原有续期/绑定资料会拒绝更新，避免新旧凭据混搭。
- 新设备确认可用后，建议停用旧设备对应账号，避免多个设备同时使用一次性刷新凭据。

## 回归与设备证明

新增三组 JVM 回归覆盖格式、合并及真实持久化故障：96 / 52 / 32 条检查。完整249个 JVM/本地HTTP测试执行任务通过；页面39/39；Android API34运行时36/36；Lint 0 Error /116 Warning。

实际 Android 系统文件选择/保存流程使用独立 `repairtest` 合成账号：下载目录生成1730字节 JSON，3家供应商共4条账号/Key导回后分池、刷新字段、停用状态与全局设置均正确；重复导入、取消及注入写入失败不改变旧数据。调试测试入口只存在于 debug 源集，不进入 Release APK。

以上不是所有第三方软件格式、所有真实账号、所有 OEM/旧系统及长时场景的保证。没有为此测试消费真实推理或新领取奖励。

# 1.2.33-test（39）本地测试说明

本轮收紧签到成功判定与一键操作反馈；源码仍在本地，未提交上传，未公开发版。

## 行为变化

- 官方明确成功/今日已签到标记，或带明确时区的今日奖励账单，才增加成功计数。缺少证据的旧记录保守降级，但保留同日防重复领取围栏。
- Loomy 每日余额信息单独显示“每日额度可用”，不当作签到成功或本次新增积分。即使刷新后余额增加，也不能仅凭余额差额推断领取。
- 小浣熊账单按固定官方路径只读分页，最多 5 页 / 100 条；去重并规范到 UTC+8。没有正证、分页不完整、日期无法确定或接口 200 而无奖励，都不当作成功。发现已有今日账单，不再领取。
- 显示“官方已确认 / 每日额度可用 / 待处理或核实”三类汇总。
- 一键操作有独立回执；当日已有结果不冒充本次新奖励。保留首次处理时间与自动/手动来源，后续查询时间单独记录。
- 昨日记录不能被今日查询失败沿用为成功。本次回执为当前服务会话内信息，服务重启后不冒充有历史回执；每日状态和领取围栏仍持久化。
- 保留供应商页共享图标、ZCode 手动领取边界及未知结果不盲目重放规则。

## 验证结果

相关 12 个 JVM/HTTP 执行任务通过，新增判定检查 48 项；完整面板 35/35。浅/深色内容宽 360/390 的四组 DOM 分别 65 项通过（headless 实际 viewport 504，不冒充真机宽度）。Release Lint 为 0 Error / 116 Warning。

原证书 v2/v3、包名/版本、ZIP CRC、打包页面和共享图标字节核对通过。指定设备 38→39 覆盖升级保留 10 账号、安装期间配置字节、管理身份和 UID。

通过实际 Android 网关重新只读核验后，汇总为 5 官方确认 / 1 每日额度可用 / 1 待核实。一键回执 0 新增、5 沿用，7 个结果均来自当日缓存，持久配置没有因本次去重操作改变。小浣熊待核实账号读取两页共 20 条返回账单仍无今日证据，不据此声称领取失败。

实际 WebView 汇总和额度卡片可见，截图及签名包已交付请求会话。此次验证没有调用领取端点或强制刷新入口。

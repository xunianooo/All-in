# Trae CN 原生接入（1.2.17）

基于 MIT 许可的 `@magpie-community/opencode-trae-auth` 0.2.31，gitHead `4578b11de27494fbbdf0d9928f94cf4468866700`，将消费版个人账号协议移植为 Java。npm 发布包完整性已按 registry SHA-512 核对。All In 不运行 Node/Bun 插件。

## 使用

供应商 → 添加供应商 → Trae CN → 登录账号。在系统浏览器完成官方授权，返回 App 后自动入池并尝试同步账号模型。模型未同步成功时，点击“同步官方模型”。签到先选账号，再点“查询状态”或“主动签到”，没有后台自动领取。登录账号的完整设备身份包含私钥，应使用现有加密备份迁移；不支持只导入 token。

## 已实现的边界

- 独立 P-256 设备身份、SPKI/PKCS8 PEM、公私钥配对和曲线校验、DER ECDSA DeviceProof；不依赖 API26 的 java.util.Base64。
- loopback 临时回调，仅指定 Host/路径/方法；回调地址为精确的 `http://127.0.0.1:port/authorize`，使用 `login_trace_id` 作一次性 nonce 校验。官方 API 回调域名精确白名单；授权失败可重新打开浏览器、重新发起授权或检查状态，旧线程由 generation 隔离。
- SOLO 后 IDE 的设备绑定交换；仅明确业务拒绝允许尝试第二客户端。不自动退回会轮换 refresh 的旧 cloudide 交换。未绑定结果不入池。
- 每账号刷新单飞；网络发送前原子持久化 pending；结果未知、崩溃遗留或发布失败时隔离旧凭据。新凭据落盘后才发布；共享配置锁、账号全文 CAS、配置 epoch、删除/禁用/恢复与旧实例退休约束。
- 按账号同步批量模型目录及有限逐函数回退，记录真实 function、model_name、图像能力、输出上限和推理档位；同名误标按上游目录评分选择。不同账号的模型权益不混用。
- Chat、Messages、Responses 共用转换与转发路径。原生签名/不透明历史仍遵守现有网关限制。工具定义、工具调用 ID 和结果完整往返；图片原内容保持，无自动下载或缩图。
- 有界 SSE 分帧、实时正文、思考、终态和错误、原生/有限文本工具解析；所有工具完整验证后交付。无终态 EOF 为失败，已发送推理请求不自动重放或切其他 function。
- 使用现有 NetworkPolicy、出站限流、RequestContext、取消、Guard、脱敏、中间件和 UsageLedger。上游没有报告的 token/缓存维度保持未知；缓存读写均零保守标未知。
- 签到使用独立稳定 15 位设备形态，聊天/续期设备不变。查询、领取和状态回读；9074 不承诺 UA 能解决，也不反复换设备领取。

## 明确限制

当前仅 Trae CN 消费版个人账号；企业租户和 Global 不支持。Max 模式需要额外上下文预算联动，尚不公布为可调用模型。部分 Kimi 复杂引用、动态引用及不能无损表示的工具/schema/图片/请求字段明确拒绝，例如 strict:true、top_p、多候选输出 n>1；不宣称完整覆盖全部插件兼容分支。推理首发后遇拒绝不会自动切 function；应重新同步目录或手动处理。签到不实现上游9074后的备用请求形态。

真实 Trae CN 账号已完成官方浏览器授权、入池、同步 29 个模型及签到。122 个真实 Eta 工具定义的首轮调用与携带 reasoning_content/tool.name 的第二轮流式往返通过；电脑反馈确认 Eta 3.4.0 已执行真实电池查询和手电筒开关。模型不支持客户端思考档位时省略字段使用默认，支持的档位与别名保留。API24/25 旧实机、29 模型全量、完整长期会话和积分账单效果不据此宣称已验证。

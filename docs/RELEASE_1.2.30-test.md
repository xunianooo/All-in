# All In 1.2.30-test（36）限流反馈与每日签到中心

此版本为本地测试交付，不代表已创建 GitHub Release。自动双平台 CI 仍保持仅手动触发，本轮不恢复自动运行。

## 限流反馈

- 确认收到上游限流时，HTTP 错误正文同时提供可读原因、重试等待秒数、冷却截止时间和来源；合法 Retry-After 继续回传。
- 没有上游等待提示时明确区分网关保护性冷却，不把它说成上游保证恢复时间。
- Chat、Anthropic Messages、Responses 的流式错误投影保留冷却说明，不把明确错误伪装成成功结束。
- 冷却按账号/模型/端点隔离，服务实例生命周期隔离；未知执行、断网、鉴权与额度不足不凭空认作限流。保留既有专用适配器、刷新围栏和重放保护。
- 原始受认可的业务码保留；Trae 的额度答案与确认的 4011 限流码分开，不在其专用冷却之外再叠加通用持有。

## 签到中心

首页新增「每日签到」入口，进入独立二级页面：今日完成数量、一键签到、逐账号结果、真实奖励/连续天数（仅上游提供时）、自动签到开关。

普通日常签到默认开启自动执行；ZCode 赠送领取仅手动确认，不加入自动或一键签到。在网关服务运行期间每天处理；关机/离线后下次启动补签，不保证 Android 强制停止服务后还能执行。

支持当前已接入且具有资格的账号：WorkBuddy 国内版、MiniMax Code、小浣熊、Loomy、Trae CN 活动签到、ZCode 赠送套餐领取。国际 WorkBuddy AI 和不支持的 API Key 明确不执行。

- WorkBuddy 先读活动状态，仅活动开放且今日未签才调用固定每日领取接口；既有上游拒绝/资格不足诚实反馈。
- ZCode 是赠送套餐领取，不等于积分签到；需要验证码时由官方客户端完成，不绕过验证码。
- 不自动领取小浣熊一次性首登奖励。
- 自动/手动/既有 MiniMax/Raccoon/Loomy/Trae 签到入口共享逐账号去重与持久写前记录；未确认的领取不在同一天盲目重复。
- 通用配置保存保留服务端签到状态，不能用旧快照抹掉记录或自动开关。
- 显示成功、已完成、活动未开放、不具备资格、需要验证码、结果未知和存储/账号错误，不把未知值捏造成零奖励或签到成功。
- Trae 的状态余额不当作本次新增奖励，未返回明确奖励就不显示虚构的获得积分。

## 验证边界

新增协议/并发/跨日/失败/读写回归，以及真实 Chromium DOM 的页面、返回、未知结果、开关、重复点击、XSS 和布局检查。最终构建、签名、设备与测试结果以交付目录和本地 evidence 为准。

尚不声称全部真实供应商奖励、第三方 Agent 展示界面、所有手机/OEM、锁屏长时均验证；网关可返回标准错误与时间，第三方客户端如何展示仍取决于自身实现。

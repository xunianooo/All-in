# All In 1.2.21 · 自动客户端兼容存底版

版本 1.2.21 / versionCode 27，基于正式 1.2.20 收录本地累计修改，Gaeul 同签覆盖升级。本次按用户要求快速存底，便于继续后续开发。

## 累计变更

- 管理边界：独立的手机私有管理身份，推理 Key 不再具有管理权限；原生 WebView/LocalBridge 自动处理管理身份。配置输出脱敏并支持秘密引用保真回写，Key 重排和未知写结果核对；显式账号导出保留。校验实际请求的 CORS/Host，限制 WebView 桥来源；Responses 原生入口纳入鉴权、隐私、预算与取消保护。
- WorkBuddy 流兼容：省略空 tool_calls/reasoning_content，正确处理空 finish_reason、跨块隐私占位符与各 choice 终止状态，保留真实工具及思考流。
- WorkBuddy 自动请求兼容：规范 developer 角色和参数，内部处理 Harness 固定句与工具描述；移除此前 DSH 用户开关。对完整、明确的 HTTP 400 通道拒绝依次尝试逗号及 system-as-user，最多三次物理发送；以进程内有界 HMAC 指纹学习适配，保护不透明历史、路径、工具参数和结果，预算失败不学习。对断连、截断或未知执行不盲目重放。
- ZCode 请求兼容：developer 到 system 的保真规范化、未知角色拒绝及 gift/native 签名边界。
- ZCode gift 并发：同账号三路并发、FIFO 等待，稳定账号刷新保持同一门闸；明确 429/3008、3009、3010 时等待 1 秒、2 秒，最多三次发送并保持请求体字节一致；持续拥挤触发有界赠送通道暂停。不因重试切换付费 Plan、账号或模型。
- 安全诊断与用量：记录兼容阶段、物理发送数、并发错误码及等待；累计已报告用量，部分 cache/reasoning 数值持久化但不冒充完整覆盖。错误体不完整记为未知，不回显上游自由文本或凭据。

## 已有验收

用户已在电脑 DeepSeek Harness 实测 WorkBuddy/deepseek-v4.1-flash 与 ZCode/glm-5.3-flash 正常。ZCode 随后的四条实际请求全部 200，其中一条确实遇到 3008，经内部三次发送及约 3 秒等待后成功，说明短重试在真实请求中生效；这些结果不构成所有模型、账号或长期后台场景的保证。

参考并校验实际 npm 发布包 WorkBuddy 0.2.25 与 ZCode 0.1.56；原函数 mock、Java 本地 HTTP 及前一轮 23 项定向套件和四项界面测试通过，包含鉴权、隐私、协议、断连、预算、排队取消和用量边界。未把本地 fixture 结果当真实上游验收，也未为测试额外消耗用户模型额度。

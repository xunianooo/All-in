# All In 1.2.27-test（versionCode 33）本地测试说明

本版用于 Trae 国内版登录问题的修复验证与诊断，尚未发布到远端。此前公开版仍为 1.2.26-test（32）。

## 变更

- 修复授权失败后清除流程、再次检查只显示“没有可检查的授权”的问题。保留失败原因和原流程，重新打开登录界面仍可恢复查看。
- 支持按已有 flowId 恢复绑定中及已结束的授权。记录失效时明确提示，不悄悄创建另一条授权。
- 保留官方授权回调中经过严格白名单校验的 authHost，供后续设备绑定使用；不接受任意站点或扩大企业账号支持范围。
- 设备绑定失败增加脱敏诊断，区分 HTTP 状态、短数字业务码、网络/TLS/设备签名问题。不会输出 Token、刷新凭据、私钥、回调链接或上游原始错误正文。
- 回调页适配手机字号，并提醒反馈时不要复制授权地址栏。
- 结果未知仍不自动重放刷新请求；未完成绑定的账号仍不会被伪报入池。

## 已有验证与边界

- 新增终态恢复回归先在旧实现复现失败，修复后通过。
- 10 个 Trae JVM/回环 HTTP 任务通过，包含设备签名、授权、账号协调、目录、协议、流式解析、控制面及网关；Release Lint 0 Error / 116 Warning。
- 面板回归 34/34；原证书 Release 构建、v2/v3 签名、包名/版本与 ZIP CRC 验证通过。
- 合成回环测试验证绑定中恢复、终态恢复、缺失流程不新建、失败诊断、凭据脱敏、HTML 回调及未知结果不重试。
- 尚未在反馈手机上复现设备绑定错误或验证修复。不能将状态恢复和诊断增强等同于真实登录根因已经解决。
- 未启动或操作 Android 设备，未读写真实账号，没有真实推理、签到、强制续期或远端发布。

## 反馈方式

使用原证书签名的测试包覆盖安装，不要卸载或清数据。进入 Trae CN，点击“重新发起授权”完成一次新的登录。

如果仍失败，仅反馈页面或 All In 中的提示和 `TRAE_BIND_...` 诊断码，以及应用版本、Android 版本；不要发送地址栏完整链接、账号密码、验证码、Token 或刷新凭据。

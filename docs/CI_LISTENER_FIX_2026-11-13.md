# Windows CI 监听夹具的反向 DNS 隔离（2026-11-13）

## 故障与范围

1.2.29-test 源码提交后的 Windows CI 在早期监听关卡失败；Ubuntu 完整流程通过。独立 TCP 控制已确认本机非回环地址可达，HTTP 响应仍未收到。原始线程栈显示 NanoHTTPD 2.3.1 在 `HTTPSession` 构造时阻塞于 `InetAddress.getHostName()` 的 PTR 查询，而不是监听 bind 或 HTTP 分帧读取失败。

本次只调整 `GatewayListenAddressOfflineTest` 的测试夹具。生产代码、资源、版本、依赖及已发布 APK 不变；这不等于修复或验收生产服务器所有 DNS/延迟场景。

## 最小隔离

- 传给原 NanoHTTPD ClientHandler 的 Socket 视图保留真实对端地址字节，只将已知数字地址作为显示名称，避免绑定语义测试依赖外部 DNS。
- 实际输入/输出流、关闭和关闭状态继续委托给原始已接受 Socket；不替换成回环地址，不更换监听实现。
- 保留全部独立 TCP 可达的非回环见证地址，不过滤虚拟网卡、不增加重试、不放宽超时。
- 保留完整 HTTP 200 和 `ok` 正文检查、截断/非法长度拒绝，以及错误收紧/错误开放监听的两个负对照。
- 新增 IPv4/IPv6 地址字节、数字主机名、回环分类、真实双向 Socket I/O 与关闭委托检查；HTTP session 同时检查实际数字对端名称。

## 验证

本机 Windows 定向监听测试通过，包含两张非回环网卡及两个故障注入负对照。完整本机回归和本次提交双平台 CI 的最终结果以对应运行记录为准；未完成的流程不声称通过。无真实供应商登录、推理、签到或 Android 设备操作。

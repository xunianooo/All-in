# R0/R1 connection coordination and outbound admission — local acceptance

This batch starts from the **local installed C1**, preserving provider management, C2 networking and C1 scheduling. The sole repository is `/workspace/All-in`, branch `main`, release baseline `147b02acfb82189669c39bcb40b3b3706171c102`, version **1.2.13 / 19**. No commit, push, version increment or release is part of this work. Original dirty files were snapshotted outside the repository before integration; additional pre-existing limiter files were retained and reviewed.

## Implemented behavior

`RequestContext` owns an explicit request ID, network snapshot, monotonic deadline, cancellation, connections and cleanup callbacks. It is captured by response wrappers rather than looked up from an unrelated writer thread. A bounded set of at most 64 model requests and a single deadline watcher bound outstanding work; no per-request worker or timer is added. Service stop cancels waits, disconnects registered inference connections and closes handed-off bodies. Actual downstream write failure cancels immediately. An idle client disconnect cannot be detected until a write or deadline; this batch makes no claim otherwise.

`AllInTrackedResponse` keeps NanoHTTPD's existing framing and single response writer. Successful wire writes advance `UNCOMMITTED → HEADERS → BUSINESS → TERMINAL`; failed writes cancel. Here body bytes are conservatively treated as business delivery: this batch injects no SSE comments and does not permit inference replay after any body delivery. Final HTTP flush notifications still reach the existing C1 two-gate wrappers. Unsent close, error, cancellation and downstream failure release reservations idempotently. The response-state machinery does not manufacture success events.

NanoHTTPD 2.3.1's `serve()` returns before `Response.send()` writes headers. The current inference dispatch remains synchronous before returning the response; sleeping inside it cannot send a heartbeat. No asynchronous held response, heartbeat or Patience loop is activated in this R0/R1 batch. A future R2 held-response implementation must select the actual response status before its writer commits headers, and use protocol errors after commitment. This is an explicit integration boundary, not a claim that SSE keepalive already exists.

`UpstreamFailure` separates ordinary rate refusal, exact raccoon `user_model_rate_limited` account throughput, quota, authentication, request validation, overload, proxy, unsent network failure and unknown sent outcome. It never grants generic same-credential replay. The exact raccoon wall applies credential-wide cooldown across models, honoring valid Retry-After and otherwise the existing 60-second fallback; it does not invent a vendor 15-minute rule. Subsequent short attempts are rejected before sending during that cooldown. Existing commercial different-key failover remains; no 2/4/8-second 429 retry loop is introduced. Sent transport failures do not broaden automatic replay. Existing special-provider fallback policies outside the admitted inference paths are not represented as a full provider rewrite.

`CredentialIdentity` uses private opaque domains scoped to provider and endpoint. Commercial IDs derive from the existing stable credential ID, never the model. Account IDs use existing `id/accountId/uid/userId`, so token refresh preserves identity. Legacy objects without such a field have weakly held process-private identity without mutating user configuration. Raccoon currently stores bearer credentials in its key list, so its bucket tracks that credential; no new OAuth refresh implementation is claimed. Deleting/replacing a key changes identity; reordering does not. State expires in memory and is not persisted across restart.

`OutboundLimiter` atomically admits a credential domain and optional provider-shared domain. Independent settings are minimum interval, rolling 60-second RPM, maximum in-flight requests, bounded queue and maximum queue time. A ticket reserves capacity before transport; `markSent` immediately before transport makes the send count permanent for the window. Closing an unsent ticket returns reservations without consuming RPM or spacing. Closing a sent ticket releases concurrency but retains rate history, including upstream refusal. The timestamp marks transport handoff, not proof of provider receipt. Uncertain transmission is conservatively counted.

Limits default to zero (unlimited rate/concurrency), with bounded request/queue safety. No vendor-specific RPM or 500/800ms default is assumed. JSON policy limits are interval/wait ≤300000ms, RPM ≤10000, in-flight ≤64 and per-domain queue ≤128. A process-wide maximum of 4096 domains and 128 waiters bounds memory. Active/rate-live domains are retained; expired idle domains can be evicted. Queue order is FIFO among overlapping constrained domains, so a waiting key does not block an unrelated key merely because both have an unlimited provider domain. Waits release the monitor and are cancellable, deadline-bound and signalled by stop/config changes. No config lock is held while waiting.

Immediate eligible alternatives are preferred before queuing; candidate readiness probes do not consume tickets or advance key rotation. Once an actual attempt waits, its C1 lease is released; dequeue reserves a fresh lease and reconnects it to the actual usage row. Existing stream row + final HTTP flush gates remain unchanged. Provider enabled state, credential existence/cooldown and request budget are checked again before sending. Upstream concurrency remains reserved through the upstream stream, not just until headers arrive.

Coverage: ordinary commercial Chat Completions, native Anthropic, native/translated Responses, and raccoon Chat inference. Each covered actual transport acquires its own ticket. Login, refresh, model catalog, usage queries, ZCode gift shortcuts, legacy native Codex/Copilot/other special adapters are outside admission coverage. The management response and UI explicitly list this boundary. No paid live provider calls were used for validation.

## Configuration and diagnostics

`GET /api/outbound` returns only limits, CAS state token and coverage. `POST /api/outbound` requires `{settings, expectedStateToken}`; strict field/type validation and section-local atomic persistence preserve provider keys, networking, groups and security. Stale writes return 409. Existing `/api/config` snapshots cannot overwrite this section. Persistence failure leaves state/token intact. Changing policy updates existing domains and wakes waiters without erasing rate history. Existing in-flight sends are not rolled back when tightening policy.

The overview contains an opt-in outbound settings card for a provider ID and credential/shared scope. Form drafts survive reads and in-flight edits, stale tokens require reload, and unknown save outcomes block automatic resubmission until readback. No real user's limits or route strategy were enabled during testing.

Usage rows gain bounded diagnostic metadata: transport handoff timestamp, queue milliseconds, failure category, an allowlisted error code and normalized Retry-After deadline. They contain no new prompt text, raw headers, bearer values or account identities. Old rows parse with empty/zero defaults; totals and C1 scoring are unchanged. Diagnostic fields are available in the recent-row API; no request logging or independent retry scheduler is added.

## Validation

- Core fake-clock tests: unsent ticket return, pacing, exact rolling window, multiple domains, queue bounds, cancellation, configuration changes and stop.
- Request coordination: phases, idempotent cleanup, stable refresh/origin identities, raccoon wall vs regular/quota 429, unknown execution, validation/CAS/persistence rollback.
- Real HTTP: cross-model spacing, RPM refusal without oversend, streaming concurrency retention/release, immediate alternate selection, policy relaxation waking waiters, stop cancelling pending sends.
- Existing C1 loopback regression includes both stream terminal gate orders, native/cross-protocol output, reset/truncation/never-sent/final-flush failures.
- Full local gate: 41 JVM suites, all commercial/native/gift/C1/stream/setup HTTP fixtures plus outbound HTTP, Debug/Release build and lint. Ten Node dashboard regressions include new outbound drafts/CAS/unknown-outcome tests. Remote CI has not run for uncommitted work.
- Independent Android `com.gaeul.allin.batchaudit` builds current production sources/assets and synthetic configuration only. C1 distribution/stream completion and outbound touch-save, cross-model actual sends, preserved sections, rolling history after policy change, stale CAS, draft preservation and narrow light/dark layout are verified. Synthetic configuration is restored afterward. Exact jobs/artifact/installed hash are recorded in the maintenance handoff.

R2 Patience/SSE heartbeat, R3 affinity and R4 provider header review remain future batches. Real provider throttle thresholds, cache hit rate and every client's timeout behavior are not inferred from loopback tests.

Continues released 1.2.15/code21, main d320a21961ff96a940c39e2b39bf9e9e727419b6. This batch is local only, without commit, push, version change or release. Related modules were implemented together and subjected to one complete gate; subsequent changes receive affected checks only.

## Offline compatibility

The bundled default_quirks.json schema/engine1 and rules1.0.0 contains three exact provider/openai/HTTPS origin/path header rules for WorkBuddy, WorkBuddy AI and raccoon. Static values come from the signed APK asset; Java restricts destination tuples, header sets, grammar, size/depth/count and printable values. Credentials, interpolation, URL/framing/authorization mutation and remote downloads are unrepresentable. A request captures an immutable snapshot before held-worker handoff and retains its version across retries. Matching connections disable automatic redirects; unmatched or failed-loading paths retain existing legacy handling. WorkBuddy AI credential-derived headers remain in Java.

GET /api/quirks reports limited version/source/count/error; diagnostics preserve a bounded rulesVersion. ZhipuEnvelope, SSE and payload logic are unchanged: no unproven migration, text/tool-argument/signature replacement or new fingerprint is introduced. Evidence demonstrates equivalence to the previous local implementation, not current vendor necessity. The fixed upstream mirror documents delegation; remote API lookup was limited and a candidate raw path returned404. No supplier inference was used to certify headers. This is the first offline header migration, not completion of all vendor adaptations or Q2 trusted distribution.

## Optional session affinity

GET/POST /api/affinity manages default-off {enabled:false} with independent CAS and legacy config preservation. Explicit session headers and authenticated scope are process-keyed hashes; prompts are never used to infer sessions. Protocol/request model/config epoch isolate keys; actual preference includes provider/base/model/stable credential identity. In-memory storage has bounded1024 entries, 30minute binding TTL, 60second initial reservation, cancellation/deadline-aware waiting outside global locks, and capacity bypass for availability. This is a soft preference, not guaranteed cache reuse.

Only eligible commercial credentials participate. Cooldown/removal/disable/R1 readiness and manual route selection take priority. C1 reservations remain active and different sessions retain normal selection. A binding requires the existing protocol-specific successful terminal observation and final downstream writer confirmation; unknown/incomplete/cancelled/failed-flush responses do not establish bindings. Config persistence and restore invalidate old epochs; late responses cannot bind to new configuration. Subscription/gift/special adapters are not claimed covered. Unsupported protocol completion paths may remain unbound.

## Local encrypted configuration backup

The native bridge offers export/import/rollback only from the exact local dashboard origin. Password entry, counts-only preview and explicit restoration confirmation are native; passwords do not enter JavaScript, config or clipboard. SAF export creates a password-encrypted file; import accepts arbitrary MIME labels but verifies content and size. API26+ is required for PBKDF2-HMAC-SHA256. Other gateway features retain minSdk24.

Version1 format uses random16byte salt, random12byte nonce, PBKDF2-HMAC-SHA256/600000 iterations and AES256-GCM/128bit tag with authenticated format header. Config is limited to4MiB, strict JSON/depth48/node100000 and validated consumed field types; unsupported future format/schema/KDF is rejected. The complete config contains accounts/tokens/API keys and routing/service settings, but not usage ledger, installation privacy HMAC key or transient session/affinity/cooldown state.

The backend reads committed durable config and uses two digest CAS checks. Service lifecycle serialization retires the old gateway (late persistence rejected), cancels active requests, stages a private encrypted prior-config snapshot, atomically replaces config and starts a fresh engine. A failed operation attempts independent stop/config rollback/restart stages; old rollback snapshot survives unsuccessful transactions. Success replaces the private snapshot; rollback itself follows the same preview/confirmation flow. The snapshot uses the import password. Task ownership cleans queued/discarded passwords/previews without concurrently clearing running cryptographic inputs. Wrong password/tampering/invalid config/CAS conflict cannot initiate replacement. Unrecoverable filesystem failure cannot be promised away.

## Validation and limits

Complete gate:51 offline suites, existing and new HTTP suites,13 dashboard suites, Debug/Release/lint. Lint94Warning, noError/Fatal. New tests cover strict immutable rules/snapshots/held-worker version retention; session reuse, distinct sessions, manual/usage behavior, invalidation, owner cancellation and failed final flush; cryptographic negatives, real temporary-file transaction faults and task discard ownership. The test-only first failure was a resource path relative to Gradle's app working directory, corrected before successful full gate.

Android isolation verifies real assets/API, two-key streaming/nonstream affinity, real touch save/CAS, narrow light/dark layout, cipher roundtrip/wrong-password/tamper/CAS/file rollback, and protocol/R2/C1/R1 plus16 native network regressions. SAF export, selecting the exported .aibk, native password/count preview, explicit restore and private-snapshot rollback were exercised in the synthetic audit backend. The snapshot was observed and the isolated gateway responded after both operations. This is not a production GatewayService restore, cross-device recovery or API26 device test. The production config was only hash-checked and retained across installation; no real account backup/restore or paid supplier request occurred.

Exact gate jobs, final source fingerprint, APK/signature/hash and evidence boundaries live in maintenance COMBINED-Q1-R3-BACKUP-HANDOFF.md and artifact-local-q1-r3-backup.json.

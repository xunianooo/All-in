# R2 patience and SSE keepalive — local acceptance

This batch continues the released 1.2.14 / versionCode 20 baseline, commit `d4c2aad30303d3228c43532ac465af67315394b4`. It is local development only: no commit, push, version increment, CI dispatch or release is part of the batch. R3 affinity and R4 header review remain separate work.

## Opt-in behavior

`GET/POST /api/resilience` manages a separate CAS-protected configuration section with `patienceMillis` (0..60000, default 0) and `heartbeat` (default false). The overview has a collapsed settings card; no real user's defaults are enabled during installation. Strict schema, stale-write 409, persistence rollback and legacy `/api/config` preservation follow the earlier network/outbound management pattern. Reads and unknown outcomes preserve drafts and do not automatically replay saves.

The candidate dispatcher first follows its existing eligible-target and key failover. Only after that pass exhausts explicit temporary rejections may it wait and revisit those rejected credentials. It preserves one logical request ID, one shared max-attempt budget and the request's original monotonic deadline. At most three additional rounds use 2/4/8 seconds plus 0..250ms jitter; the elapsed patience window begins at the first exhausted pass and is also bounded by the original request deadline. Waiting holds no config/scheduler lock or C1 attempt lease. Every actual retry still passes R1 admission and validates enabled/credential/cooldown state.

Patience replay is limited to commercial-key channels with unified credential cooldown revalidation. Special subscription/native adapters, including raccoon, retain existing fallback and do not enter new patience rounds; their legacy REST ranking is not represented as a strict no-send gate. Same-credential replay is allowed only for structured HTTP429 codes `rate_limit`, `rate_limit_error`, `rate_limit_exceeded`, `requests_rate_limited`, or an error with type `rate_limit_error` and no code; HTTP503 requires explicit structured `overloaded_error`. Every nonempty structured code/type must agree with that rejection family; conflicting or unknown values are excluded. This is a conservative rejection allowlist, not a guarantee that arbitrary JSON/body text establishes nonexecution. Generic 5xx, network/proxy failure, sent outcome unknown, request/signature errors, authentication, quota/balance and raccoon `user_model_rate_limited` do not enter patience. A retry round contains only the previously explicit-rejected credentials, so clearing per-round selection state cannot reintroduce a hard-failed key.

Valid Retry-After seconds/date uses the existing strict parser. Missing or invalid values retain a conservative 60-second cooldown, so the normal 20-second experiment cannot silently bypass unknown 429 with a two-second retry. If the required wait exceeds remaining patience or attempt budget, return the final error rather than sleep beyond the budget. No default vendor RPM, balance prediction or 15-minute wall rule is introduced. Existing noncommercial special adapters retain their previous fallback behavior; the new patience allowlist is not a general redefinition of every legacy policy.

## Held responses and transport

For standard POST `/v1/chat/completions`, `/v1/messages`, `/v1/responses` with JSON `stream:true` and heartbeat enabled, auth and the existing bounded UTF-8 ingress read complete before handing work to a bounded executor (4 workers, 8 queued tasks). The request context, policy and immutable network snapshot are explicitly captured; the worker establishes and clears its request thread state. Special native aliases, Gemini and nonstreaming do not get injected SSE. Nonstream patience remains synchronous and cannot refresh a client's socket idle timer.

`AllInHeldResponse` lets the only response writer wait for a supplier result. If a result arrives before the first three-second heartbeat, its HTTP status, headers and body are preserved. If still pending, the writer commits HTTP200 with an SSE comment and emits another comment approximately every three seconds. After that commitment a late failure becomes Chat error, Anthropic `event:error`, or Responses `response.failed`; it never changes the HTTP status or fabricates a successful stop/[DONE]. Late per-attempt upstream headers cannot retroactively change already-sent headers.

The same bounded worker pumps successful SSE bodies through at most eight 8192-byte queue chunks, plus the producer/read buffers. This supplies bounded backpressure rather than unbounded streaming accumulation or a new thread per request. Heartbeats continue during body stalls **only at complete SSE event boundaries**. No comment is inserted inside partial event/UTF-8 data; a peer stuck mid-event may still hit client timeout. A boundary failure emits a protocol error; failure or ordinary EOF in a partial event aborts the stream instead of corrupting syntax, reports unsuccessful delivery, and does not append a normal terminating HTTP chunk. Worker saturation is explicit 503; the entire request remains deadline-bound. Heartbeat mode disables response gzip so comment flush timing is not hidden by compression.

Comments and HTTP chunk framing do not advance RequestContext BUSINESS phase, TTFT or token/attempt counters. Real upstream bytes advance the business phase only after successful wire write. Existing C1 row/protocol success and final HTTP flush callbacks survive the held wrapper; downstream reset, never-sent close, final-flush failure and upstream error settle failure once. An upstream body pump may finish before downstream delivery, but successful C1 usage remains gated on final delivery. The original stream model alias is captured before crossing executor threads.

Stop/cancellation signals waiters and held tasks, disconnects registered connections and closes sources; a queued future that never starts is also cancellable. Cancelling on the bounded ThreadPoolExecutor removes that queued task immediately so abandoned requests do not retain admission capacity. Idle client disconnect is detected on a heartbeat write (or business write/deadline), not by an imaginary immediate peer-disconnect callback. If cancellation occurs after headers, it produces a protocol error only where safe; actual socket failure simply ends delivery.

## Verification and limits

Core main-style tests cover settings defaults/types/CAS/rollback, rejection allowlist, Retry-After, fake monotonic patience window and backoff. Held-response tests cover early status/headers, three late error protocols, no business callback from comments/framing, final-flush failure, fixed-length early EOF, never-sent/late disposal, queued cancellation, bounded slow-consumer backpressure, body stall heartbeat and partial-event protection.

Real loopback HTTP covers 429→wait→success, explicit overload→success, hard-error no replay, Retry-After beyond budget, multiple rejected passes with actual heartbeat then success, all three protocols' late errors, body stalls, one logical terminal/attempt accounting and C1 release, and cancellation without ongoing retries after failure detection. Existing commercial/native/gift/C1/stream/setup suites remain in the full gate. New front-end regression covers dirty drafts, in-flight edits, strict values, stale reads, conflict and unknown-save guards.

Independent Android synthetic audit verifies real touch save, provider/network/group preservation, patience+heartbeat success, body-stall heartbeats, late error without fake stop, hard cooldown no send, narrow light/dark layout, and C1/R1 combined regressions. Maintenance-only probes now exercise installed ETA 3.4.0 actual OkHttp and its obfuscated SSE parser, including a local POST through the isolated All In gateway: 4-second cloned read timeout, a 7-second upstream body stall, two approximately 3-second comments, and subsequent business data completed without timeout. A separate 1-second silent control times out. The original client remains unchanged; exact results and transport/time scaling are recorded in the maintenance artifact. It must not be represented as a five-minute end-to-end production model timeout test or a full ETA Agent run. No real provider configuration or paid inference calls are used.

Exact gate jobs, artifact hashes, device installed/config checks and any incomplete client compatibility coverage are recorded in `R2-RESILIENCE-HANDOFF.md` and `artifact-local-r2.json` outside the source repository. Local validation does not imply remote CI or computer-agent acceptance of this batch.
